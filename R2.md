## Active delivery ledger — 2026-08-07

This is the operational view of the roadmap. `R0.md` remains the evidence
baseline, `R1.md` the full capability catalog, and `R3.md` the provider/decision
register. Update this ledger whenever an item is selected, a gate is resolved,
a design starts, or acceptance evidence changes.

Status has a strict meaning: **Ready** permits the stated next deliverable;
**Course stop** requires tutor evidence before design; **Designing** permits only
the linked design scope; **Experimental** means code and tests exist but does not
claim production completeness. An open adjacent gate may limit a Designing item
without reopening the part already reviewed.

### Ledger update rule

Every advancing work session must leave five facts unambiguous here or in its
linked row: current lifecycle state, applicable open/resolved gates, reviewed
evidence/design link, one next concrete deliverable, and the claims still
forbidden. “Implemented” without test evidence, or “blocked” without the exact
unblock condition, is not a valid ledger update.

## Recommended build sequence

### F0 — trustworthy substrate

Build `finance_core`, `finance_provenance`, `finance_http`, `finance_table`, and
`finance_testkit`, then the shared track/status/capability foundations and the
`pi_finance_setup`, `pi_finance_track_status`, `pi_cn_setup`, `pi_hk_setup`,
`pi_finance_guardrails`, and `pi_finance_symbols` plugins.

Acceptance:

- one canonical observation envelope is used across packages;
- secrets are redacted from tool results and errors;
- identifier ambiguity and stale data are observable test cases;
- OpenFIGI uses v3 rather than the retired v2 API;
- provider HTTP behavior has deterministic fixtures and rate-limit tests.

### F1 — first equity research agent

Build `pi_stock_quote`, `pi_stock_history`, `pi_sec_edgar`, `pi_sec_xbrl`,
`pi_stock_fundamentals`, `pi_watchlist`, and `pi_stock_research_report`.

The quote/history, SEC, fundamental, branch-persistent watchlist, and narrow
source-fact report slices are Experimental. Authoritative security resolution,
user-owned cross-session watchlist storage, cryptographically bound cross-tool
receipts, and full automatic orchestration remain open, so F1 is not yet
complete.

Acceptance: given a US-listed company, Pi resolves the security, gets a properly
labelled quote/history, finds primary filings, extracts a small audited set of
fundamentals, and produces a cited report. The same run can be reproduced from
an evidence manifest without a model call to fetch facts.

### F2 — monitoring and analysis

Add corporate actions, earnings calendar/releases, filing diff/monitor,
screening, peers/comps, valuation, technicals, news, catalysts, alerts, the
shared indicator/strategy/execution contracts, trade planning, and the first
complete swing-trader workbench.

Acceptance: a saved watchlist produces a bounded, sourced morning brief and
alerts survive `/new` and `/fork` correctly while stopping cleanly on reload or
session shutdown. A swing candidate can be replayed from a point-in-time
universe through its exact feature evidence, catalyst/sector context, entry,
invalidation, target, risk-sized quantity, alert, and post-trade review without
changing definitions between the screener, planner, simulator, and journal.

### F3 — portfolio agent

Add portfolio import, risk, scenarios, attribution, thesis tracking, journal,
governance/industry context, the investor workbench, and rebalance proposals.

Acceptance: every portfolio result reconciles to imported positions and a dated
price snapshot; risk/valuation outputs expose methods, assumptions, missing
data, and sensitivity rather than a single unexplained score.

### F4 — asset-class breadth

Add FRED/ALFRED macro data, official rate/FX sources, options, fixed income,
CFTC positioning, commodities, crypto, and global markets according to demand.

Acceptance: shared types handle calendars, currencies, units, contract identity,
and different data frequencies without equity-specific shortcuts.

### F5 — paper execution

Add one read-only broker adapter, its paper-only execution companion, and trade
policy/audit plugins. The broker adapter must consume the already exercised
`finance_execution` order/cost semantics rather than define a second model. Run
paper-only for an extended period with fault injection.

Acceptance: duplicate calls do not duplicate orders; every transition is
reconciled against the broker; UI-less mode cannot submit; stale quotes and
policy violations fail closed; all lifecycle cleanup is idempotent.

### F6 — optional live execution

Only consider a broker-specific live plugin after a separate threat model,
security review, operational runbook, and explicit user decision. A generic
provider-independent live order tool should not be the first design.

### T0–T4 — four-trader workflow convergence

This acceptance sequence cuts across the finance feature phases. It does not
create four new data stacks:

1. **T0 shared decisions — `CG-TECH`, `CG-RISK`, bounded `CG-DAY`
   execution-information, and `CG-QUANT` shared-replay slices resolved; full
   day workflow remains a course stop:** extend `finance_indicators`, `finance_risk`, and
   `finance_execution` incrementally; add trade-plan and order-
   simulation tools using the same definitions as alerts, backtests, journals,
   and later paper brokers.
2. **T1 swing trader — `CG-SWING` Resolved — 2026-08-06:** deliver the first
   complete professional daily loop using trustworthy
   daily data, point-in-time screening, sector/catalyst context, risk sizing,
   next-session preflight, monitoring by exception, and review on each track
   that passes its daily-data evidence coverage. The resolved
   contracts now compose in seeded offline and bundled-tool journeys, and one
   opt-in configured-tutor sequence proves LLM-owned plan, preflight, monitor,
   replay, review, and journal selections, then exact workbench restoration in
   a second Pi process. The market leaves are now copied from bundled-provider
   tool results over exact scripted bytes. Sector/catalyst breadth, exact
   task-time observations, distinct-session durability, and complete task
   evidence remain the next vertical gaps. Those
   omissions stay visible facts rather than plugin readiness decisions.
3. **T2 long-term investor — course stop `CG-FUNDAMENTAL`:** require primary
   documents, sufficiently complete
   statements/segments/debt, actions/dividends, governance, industry/peers,
   valuation, portfolio fit, and thesis review. Each report lists missing
   dossier sections rather than scoring an incomplete record.
4. **T3 quant researcher — `CG-QUANT` shared-replay slice resolved:** compose
   the implemented provider-neutral information core with point-in-time universe and availability
   data, adjustment/action truth, reproducible feature/strategy definitions,
   explicit execution costs, out-of-sample or walk-forward validation, trial
   accounting, uncertainty, and dataset/run manifests.
5. **T4 day trader — full-workflow `CG-DAY` remains a course stop; the `CG-PSYCHOLOGY` journal-information slice alone is insufficient:** deliver only
   after a chosen track has licensed intraday
   quote/trade/depth data with bounded freshness and sequence gaps, exact
   auction/session/halt rules, bounded alert latency, order simulation, and
   execution-quality review. Daily-bar or delayed public-web adapters cannot
   satisfy this gate.

Each checkpoint needs deterministic offline fixtures and a scripted end-to-end
journey phrased in trader language. Completion means the trader can perform and
audit the decision loop, not merely that every named tool is installed.

### CN0–CN4 — China parallel track

The China track can begin alongside F1 without waiting for US feature breadth:

1. **CN0 identity/rules:** `pi_cn_stock_symbols`, `pi_cn_market_calendar`, and
   `pi_cn_stock_rules`.
2. **CN1 primary research:** announcements, financials, quote/history, and the
   first China company report.
3. **CN2 market structure:** corporate actions, earnings, share structure,
   unlocks, pledges, public information, margin, block trades, and Stock Connect.
4. **CN3 analysis:** China screener, industries/concepts, indices, valuation,
   filing diff, watches, regulatory events, and macro/policy context.
5. **CN4 breadth:** Beijing-specific edge cases, convertibles, funds/ETFs, IPOs,
   Hong Kong/A-H comparison, and only then read-only/paper broker work.

As of 2026-08-05, the CN/HK substrate is Experimental. Isolated identity,
official 2026 calendar, public-web quote/history and narrow exact fundamental
workflows, official dated rule, and official disclosure-discovery shells compose
shared evidence, HTTP, math, coverage, and capability policy. `cn_setup` and
`hk_setup` are loadable track-labelled preflights; with all matching tools each
covers the ten current feature families. Authoritative venue identity,
production data rights, exceptional rule/calendar state, official filing-linked
statement depth, broader accounting, and redistribution remain visibly
incomplete under `CN_TRACK.md` and the structured status receipt.

CN1 acceptance: Pi can take an unambiguous Shanghai, Shenzhen, or Beijing
listing, show a source/freshness-labelled quote, retrieve original disclosures,
normalize a small audited set of financial fields without losing Chinese units
or statement scope, and produce a cited report containing the original Chinese
source titles.

## Suggested next trader-requirement sprint

The original substrate and narrow US-research sprint is Experimental. Bounded
daily acquisition and exact gap joins exist on all three tracks, but adjustment
provenance, source rights, freshness, and volume/turnover semantics are not yet
strong enough to call the complete swing input trustworthy. The next vertical
slice should close that loop without making day-trading claims from daily data:

1. **`CG-MARKET-DATA` and `CG-TECH` resolved; first information/calculation
   slices Experimental:** incrementally compose the daily observation contract
   into provider receipts and extend `finance_indicators` beyond its implemented
   SMA/Wilder RSI/true-range/Wilder ATR core with EMA/MACD, Bollinger, KD,
   volume relations, explicit technical primitives, and requested projections.
   Preserve exact policies and receipts without plugin-owned correctness,
   sufficiency, readiness, interpretation, candidate, or next-action judgments.
   Defer intraday VWAP until compatible intraday observations exist.
2. **`CG-SWING` and `CG-RISK` resolved; evidence/calculation cores
   Experimental:** preserve the implemented network-free
   `finance_strategy` definition, evidence compatibility, LLM/user plan
   declaration, structural transition, and receipt slice. It exposes true,
   false, unknown, missing, stale, late, conflicting, unsupported, warm-up, and
   expiry/history facts but produces no setup, trade, or plan verdict. The LLM
   remains the only decision-maker as `finance_risk` and `finance_execution`
   receipts are composed and later coverage becomes available.
3. **`CG-DAY` execution-information slice resolved; first core Experimental:**
   compose exact desired/capability facts, explicit depth/daily-bar scenarios,
   lifecycle/fill leaves, and requested costs into the swing shell. Extend
   dated tick/lot and fee evidence incrementally while keeping models
   LLM-selected and every order non-executable.
4. Strengthen `pi_stock_screener` and `pi_stock_technicals` to emit the same
   versioned evidence consumed by saved setups and alerts, and render it through
   `pi_finance_charts` without duplicating calculations.
5. Graduate `pi_trade_plan` to Designing as a thin shell over exact
   `finance_risk` facts and explicitly requested operations. It may expose
   independent bounds, grid projections, comparisons, and receipt handles, but
   must not choose a quantity, validate a plan semantically, or select a next
   operation.
6. Extend the Experimental `pi_swing_workbench` context shell over screener,
   sector/catalyst context, watchlist, plan, alert, and journal receipts as one
   professional daily rhythm. Preserve exact facts and the working set across
   interruptions, do not add another provider client, and leave every
   interpretation and operation choice to the LLM.
7. Make `pi_order_simulator`, `pi_backtest`, and `pi_trade_journal` replay that
   exact strategy/execution version so planned, simulated, and observed outcomes
   are comparable.
8. Extend the seeded offline CN/HK/US journeys with explicit facts for gaps,
   stale evidence, insufficient warm-up, ambiguous identity, an unfilled limit,
   a gapped stop, lot-grid mismatch, and a losing trade with a caller-authored
   review. Preserve all branches and let the LLM interpret every outcome.

This sprint makes the existing substrate useful to a trader while exposing
track-specific data and rule gaps honestly. It precedes licensed intraday/day-
trader work and broker submission.
